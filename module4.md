Module 4: Trained consensus selector + LIME
What this bundle changes
- Trains a separate SGD consensus classifier from Dataset/Current_Network_Metrics.csv and its consensus target.
- Stores its artifacts under FL_SGD/consensus_selector/; existing federated fraud model files are not overwritten.
- Uses LIME with representative rows from the metrics CSV to explain the trained selector.
- Removes the old random-row consensus prediction from transaction submission.
- Keeps the model recommendation separate from network.consensus_mode, the mode actually used by block forging.
- Shows per-feature source labels. Dataset-derived features are labelled simulated/project data; application node count and transaction risk are labelled according to their actual source.
Required CSV columns
node_count, network_latency_ms, tx_throughput_tps, energy_joules_per_min, security_risk_score, vehicle_count, vehicle_count_variability, fault_tolerance_requirement, consensus
The consensus column must contain valid labels: PoW, PoS, PBFT, Raft, or HotStuff.
Install and train (PowerShell, from project root)
python -m pip install pandas numpy scikit-learn joblib lime
python train_consensus_selector.py
python app.py
Open Module 4 and click Refresh explanation. Review FL_SGD/consensus_selector/evaluation.json before reporting any accuracy.
Research caveat
A supervised classifier learns the labels provided in the CSV. If those labels were generated by a predefined policy, the model will imitate that policy; LIME explains the learned classifier but does not prove that its protocol choices are optimal. For a stronger research claim, collect controlled measurements for each protocol (latency, throughput, packet loss, energy/resource use, finality, failures), define a documented target/utility criterion, and compare the selector against fixed-protocol baselines on held-out scenarios.
Data provenance caveat
The application only knows its own registered application nodes; this is not automatically the number of physical network peers. Dataset values are not live measurements. Missing required features are not silently filled with zero; they can be sourced from the latest valid dataset row with an explicit simulated/project-data label.
